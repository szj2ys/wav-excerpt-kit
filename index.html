A local recording-review kit

Give each audio excerpt an exact route back.

Choose explicit PCM frame ranges, export separate WAV files, and keep a reproducible manifest of where every frame came from.

This small Python kit prepares audio for a reviewer. It does not listen, transcribe, translate or decide where a sentence ends.

1. Reproduce a tiny example first

Extract the ZIP into a new private folder and open a terminal there. Check python --version. Then run these commands one at a time. The fixture contains mathematical samples, not recorded speech.

python wav_excerpt.py fixture demo.wav
python wav_excerpt.py info demo.wav
python wav_excerpt.py plan demo.wav --recipe example-ranges.json
python wav_excerpt.py export demo.wav --recipe example-ranges.json --out review-packet
python verify_packet.py demo.wav review-packet

info shows 12 stereo frames at 8,000 Hz. The 104-byte source has an odd metadata chunk, so its PCM starts at byte 56. The complete plan lists both windows, filenames, predicted hashes and the total size. A plan creates no audio files.

Check complete source reconstruction

This second recipe covers all source frames in three windows. It explicitly includes a short final window, without dropping a remainder.

python wav_excerpt.py export demo.wav --recipe example-partition.json --out full-partition
python verify_packet.py demo.wav full-partition

The result confirms that joining the three PCM payloads reproduces all 48 source PCM bytes. Do not join whole WAV containers.

2. Write a selection you can repeat

Keep your original recording. Read its supported format and frame count with info, then copy and edit an example recipe. Choose enough context using your usual player or editor; this kit cannot hear whether a cut is useful.

{
  "version": 1,
  "allow_overlap": false,
  "ranges": [
    {"start": 2, "end": 5, "label": "A private review note"}
  ]
}

A range is zero-based and end-exclusive: [2,5) means frames 2, 3 and 4. A stereo frame has one sample per channel. Frame 2 at 8,000 Hz is exactly 2/8000 seconds into the sample stream, not a recording wall-clock time.

  • Require integer values with 0 ≤ start < end ≤ source frames. No decimals, rounding or clamping.
  • Range order stays as written. Overlap rejects unless you explicitly set allow_overlap to true.
  • Labels are optional, limited to 120 Unicode code points, and never used as paths. Unknown or duplicate fields reject.
  • List each range explicitly. There is no automatic silence, word boundary or fixed-duration splitter.

Run plan with your recipe and inspect every range before export. One invalid range prevents the batch, even when earlier ranges are valid.

3. Hand over files with their source map

Each excerpt has a safe ordinal filename. Its manifest records the source and output SHA-256 hashes, format and frame counts, absolute source byte slice, exact rational times, your recipe and omitted metadata. For output frame j, the original frame is start + j.

The separate verifier uses Python's wave reader for outputs and compares real PCM bytes with the original. Repeating the same source, recipe and tool version produces deterministic files. The manifest has no volatile timestamps or absolute source path.

The handoff still contains private material. Excerpts contain the selected speech, and labels may be sensitive. Share only with intended reviewers. Metadata removal is not anonymization; a hash does not authenticate the speaker or prove review completion.

For the human follow-up, use the PewTranslate guide to checking transcript and translation errors. Return to the recording when wording is uncertain. Exact sample bytes cannot verify meaning.

Know what this copy preserves

Exact selected PCM frames: same sample integers, interleaved channels, rate and width. No gain, fade, downmix, normalization or resampling. An abrupt boundary can click or remove context.

Fresh containers: every output has a new minimal WAV header. Opaque source chunks are omitted and listed by hexadecimal ID and size. Cue points, loop information and recording-time metadata are not carried into shortened files.

Supported format and hard bounds

Little-endian RIFF/WAVE tag 1, signed PCM16, mono/stereo, 8,000–96,000 Hz; one nonempty data chunk and one fmt chunk in either order. fmt16 or fmt18 with zero extra count only. Every outer extent, odd padding, rate, alignment and complete frame is checked. Unknown metadata receives no semantic validation. RF64, RIFX, float, compressed and extensible formats are unsupported.

  • Source: 64 MiB; 256 chunks.
  • Recipe: 1 MiB; 1–1,000 excerpts; at most four nested JSON containers.
  • All planned WAVs: 256 MiB, counting repeated overlapping frames and headers.
  • Manifest: 4 MiB. Bounds reject; nothing is silently truncated.
Existing files and failed writes

Export accepts only a new simple folder name in the current directory. It refuses existing destinations, path traversal and reserved device names. Source and recipe are read-only.

After validation, files are written and checked in a unique staging folder. Windows finalization refuses a destination that appears late. Failure returns nonzero and reports any staging left behind; no recursive cleanup runs. Inspect that exact private staging folder before manual removal. This is not a power-loss guarantee or a defense against someone changing your working directory.
